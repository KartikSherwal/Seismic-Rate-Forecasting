# Earthquake Seismicity Forecasting

Two linked projects: a classical-ML baseline that predicts earthquake magnitude, and a
reframed time-series approach that forecasts **regional monthly seismic activity** using
engineered features and a sequence model built after diagnosing and fixing a data-leakage
problem in the first version.

Both are runnable end-to-end, and both come with a script that takes new input and produces a
live forecast rather than just re-running a notebook cell.

---

## Why two approaches

The first version of this project predicted an earthquake's **magnitude** from its location and
its seismic-network metadata (station count, azimuthal gap, distance to nearest station,
location-fit residual). That framing has a leakage problem: those metadata features are only
known *after* a quake is detected and processed a bigger quake is picked up by more stations,
so the model was partly reading the answer off the back of the card. It also used a random
train/test split on time-ordered data, which further inflates the score.

`main.ipynb` measures this directly (random vs. temporal split, permutation importance, a
geo-only ablation) before landing on a corrected, deployable framing: **forecast rates, not single
events**. `earthquake_forecasting_lstm.ipynb` builds that forecasting approach on the full USGS
catalog binning the globe into 5°×5° monthly cells and predicting next-month event counts and
the probability of a significant (M ≥ 5.5) event, benchmarked against several baselines before
introducing an LSTM.

## Quickstart

```bash
git clone <your-repo-url>
cd <your-repo-name>
pip install -r requirements.txt
```

### 1. Run the notebooks (in order)

```
jupyter lab main.ipynb                          # classical model + leakage diagnosis
jupyter lab earthquake_forecasting_lstm.ipynb    # forecasting pipeline + LSTM
```

`earthquake_forecasting_lstm.ipynb` downloads the full USGS catalog on first run (5–15 minutes,
cached afterward) and needs `pip install tensorflow` for the LSTM cells specifically everything
else in it runs on scikit-learn alone.

### 2. Predict a single earthquake's magnitude

```bash
python predict.py --latitude 10.93 --longitude -62.78 --depth 122.29 \
                   --nst 67 --gap 92 --dmin 3.959 --rms 0.97
```
or run `python predict.py` with no arguments for an interactive prompt, or `--csv file.csv --out predictions.csv` for batch scoring.

### 3. Forecast next-month regional activity

```bash
python predict_lstm.py
```

This walks you through either looking up a region already in the historical panel, or typing in
your own recent monthly earthquake counts (e.g. numbers you pull from the
[USGS Earthquake Catalog](https://earthquake.usgs.gov/earthquakes/search/) for a region you care
about) — no need for the full dataset to try it. For scripting, `python predict_lstm.py --cell
"35_140"` looks up a saved region directly.

## Methodology summary

| Stage | What was done |
|---|---|
| Data | USGS FDSN Event API, M ≥ 4.5, 1990 → present |
| Leakage diagnosis | Random vs. temporal split comparison, permutation importance, geo-only ablation |
| EDA | Catalog completeness, Gutenberg–Richter fit (b-value), magnitude of completeness, depth structure, spatial distribution |
| Reframing | 5°×5° spatial cells × monthly bins → a genuine time-series forecasting panel |
| Features | 17 engineered features per timestep: rolling counts/energy (3/6/12-month), volatility, rolling b-value, months since last significant event, seasonal encodings |
| Split | Strictly chronological (train ≤ 2013, val 2014–2018, test 2019→present); scaler fit on train only |
| Baselines | Persistence, rolling mean, per-cell climatology, gradient boosting |
| Model | Stacked LSTM (64→32) with dropout, Huber loss (regression) / class-weighted BCE (classification) |
| Evaluation | MAE/RMSE/R² for counts; ROC-AUC, PR-AUC, Brier score, and Brier skill score vs. climatology for classification |

Full reasoning for each choice  including why persistence and climatology are strong baselines
here, and what a good vs. weak result actually looks like is in the markdown cells of
`earthquake_forecasting_lstm.ipynb`.

## Limitations & next steps

- Deterministic prediction of a single earthquake's time, place, and magnitude is not attempted 
  it's an open problem in seismology. This forecasts *rates*, consistent with how operational
  systems like the USGS's aftershock forecasts and the academic ETAS model approach it.
- Each grid cell is modeled independently; seismicity is spatially coupled across neighboring
  cells, which a graph neural network over cell adjacency would capture better.
- No declustering (e.g. Gardner–Knopoff) is applied, so aftershock sequences and background
  seismicity are modeled together rather than separately.
- `predict_lstm.py`'s manual-entry mode reimplements the notebook's feature engineering
  independently rather than importing shared code fine for a demo, but a shared module would
  guarantee train/serve consistency in a real deployment.

## Data sources
